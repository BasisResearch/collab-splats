Dashboard Architecture — 3 Approaches

Which direction feels right? Click to select.

A

Targeted fix — Panel shell + native viewers

Keep Panel for all Python callbacks (run extraction, run reconstruction, progress bars, state). Replace the 3 slow components with browser-native viewers served from a small static file server:

  • Video player → HTML5 <video> served as file (already partially done)
  • Image strip → <img src="/frames/frame_0100.jpg"> URLs instead of base64 thumbnails
  • Mesh/pointcloud → Three.js viewer in an <iframe> inside Panel

Pros

  • Minimal risk, incremental
  • All Python logic unchanged
  • Fastest to ship

Cons

  • Panel overhead remains
  • iframe embedding is awkward
  • Still fighting dynamic=True tab bugs
B

Hybrid — FastAPI backend + HTML/JS frontend

Thin FastAPI server exposes Python pipeline as REST/SSE endpoints. HTML+JS frontend (vanilla or minimal framework) handles all rendering. Panel is removed entirely. Python logic is unchanged — only the UI layer changes.

  • FastAPI serves frames, video, mesh as static files + REST endpoints
  • Server-Sent Events (SSE) stream reconstruction/extraction logs to browser
  • Three.js for pointcloud/mesh, native <video> for video, <img> for frames
  • Each pipeline tab = one HTML page (or SPA sections)

Pros

  • Fluid like the viewers you liked
  • Full control over layout and UX
  • No Bokeh/Panel overhead
  • Easy to extend with new visualizations

Cons

  • Need to rewrite UI layer (~2-3 days)
  • Need REST endpoints for each operation
  • Lose Panel reactive widgets
C

Full replace — FastAPI + rich SPA

Like B but with a richer frontend: a proper single-page app with routing, state management, and a component system (e.g. Alpine.js or Svelte). Maximum control, maximum effort.

  • Dedicated frontend build step (Vite + Svelte or similar)
  • Component-based UI matching current 5-tab structure
  • WebSocket for real-time progress (richer than SSE)
  • Could look as polished as a commercial product

Pros

  • Best UX ceiling
  • Maintainable long-term
  • Full design freedom

Cons

  • Significant frontend build complexity
  • ~1-2 weeks to replicate current features
  • New toolchain to maintain
My recommendation

Option B. FastAPI + vanilla HTML/JS gives you the fluid feel you liked (same tech as the viewers I built) without the complexity of a build pipeline. SSE handles live log streaming cleanly. Can be built incrementally — ship Preprocess tab first, then Reconstruct, etc. Panel is deleted when each tab is replaced.
