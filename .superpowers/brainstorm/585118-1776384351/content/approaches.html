How should we scope this work?

6 issues across feature extraction, dashboard UX, and preprocessing — three ways to package them

A

Bug-fix PR only

Fix the 5 concrete bugs in one PR: missing deps (transformers), upside-down images (cv2 orientation), image max-size, tab indicator, explore tab restructure. Skip optical flow.

Pros

  • Ships fast, low risk
  • No new architecture

Cons

  • Leaves optical flow out entirely
B

Bug fixes + dashboard UX (1 PR) + optical flow (separate PR)

All 5 bug fixes in one PR on the current branch. Optical flow frame sampling (SplatterConfig option + dashboard integration) lands as a separate stacked branch after.

Pros

  • Clean separation — UX fixes vs new capability
  • Optical flow PR is self-contained and reviewable
  • Matches existing stacked PR train strategy

Cons

  • Two PRs to merge instead of one
C

Everything in one branch

Bug fixes + explore tab redesign + optical flow preprocessing all together.

Pros

  • One review cycle

Cons

  • Bigger diff, harder to review
  • Optical flow is new capability mixed with bug fixes

⭐ Recommended: B — clean separation, fits stacked train
