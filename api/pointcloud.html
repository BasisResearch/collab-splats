Point Cloud#

collab_splats.pointcloud builds a PointcloudResult (points, poses, depth, per-pixel provenance) from the scene’s images/ keyframes through one of two backend families, picked by pointcloud.method: feedforward (vggt_omega default, vggtx, mapanything, loger) or sfm (instantsfm, colmap, hloc, each with VDA metric depth). Config keys: Reconstruction Pipeline Configs.

Output layout, per backend:

<scene>/<backend>/
  pointcloud.zarr                  depth, images, poses, K; attrs (sfm: method, backend,
                                   registered_frames, total_frames, depth alignment)
  colmap/sparse/0/*.bin            COLMAP model, image names = frame stems
  sparse_pc.ply
  depth_vda/images/npy/<stem>.npy  sfm only: VDA metric depth, 518-wide
  colmap/instantsfm.db             instantsfm only: SIFT database (not pushed)
  colmap/colmap.db                 colmap only: SIFT database (not pushed)
  colmap/hloc/                     hloc only: h5 features/matches, pairs, sfm/ mapper dir (not pushed)

The reconstruction contract every pointcloud backend returns.

  • PointcloudResult: points, cameras and dense per-frame arrays, saved to and loaded from zarr

  • two Ks per frame: intrinsics on the full-res frame, model_intrinsics on the model grid

  • COLMAP is export-only (to_colmap), never loaded

  • BasePointcloudCreator: create_pointcloud template; subclasses implement _reconstruct

Bundle adjustment with loop closure#

Feedforward only; the solver itself is in Geometry. With pointcloud.loop_closure and pointcloud.bundle_adjustment.enabled both on, pointcloud.bundle_adjustment.strategy picks the solve:

  • global (default): plain LC windows, then the refine stage solves every frame at once

  • window: BA inside each loop-closure window, before its submap enters the pose graph; refine is dropped from the default stage set, and naming it explicitly raises ValueError

  • window+global: both, in that order

Window solves:

  • the first window refined with refine_focal sets the focal; later windows hold it fixed

  • a window whose solve raises ValueError keeps its feedforward poses, with a warning

  • per-window records (start, n_frames, ok, alignment_scale, loss_final, focal, seconds, gpu_max_mib) land in the pointcloud.zarr attrs under window_ba

Depth alignment (sfm path)#

  • no confidence (None): sfm has no per-pixel confidence

  • weights: Metric-Video-Depth-Anything-Large, CC-BY-NC-4.0 (non-commercial); VDA code Apache-2.0

The loger backend#

LoGeR: a Pi3 backbone plus a TTT fast-weight memory, run with sliding-window inference. Install with bash setup/loger.sh (vendors Junyi42/LoGeR @ 7685b7a); weights download from HuggingFace on first use.

  • for long, ordered captures; refuses loop_closure

  • K is fitted, not predicted: estimate_intrinsics_from_points solves one shared K from the pointmap; a degenerate fit raises RuntimeError

  • preproc.max_frames (default 300) caps the frame count; raise it to use LoGeR’s windowing

LoGeR feedforward backend: sliding-window Pi3 with a test-time-trained memory.

  • predicts no intrinsics; one K is fitted from the camera-frame pointmap

  • vendored: github.com/Junyi42/LoGeR @ 7685b7a (setup/loger.sh -> third_party/LoGeR/)

  • cites: loger/models/pi3.py:59, 172, 584-596, 772-775; loger/utils/basic.py:21, 53-63

  • read, not a dependency: github.com/PolyCam/LoGeR @ 5d7c1a7, run_loger.py:47-164, 481

  • neither fork ships a LICENSE; nothing is copied

SfM backends#

pointcloud.method: sfm dispatches pointcloud.backend through SFM_CREATORS: instantsfm (global), colmap and hloc (incremental). Every sfm backend:

  • is experimental: the stage emits a UserWarning

  • refuses loop_closure (ValueError at config validation)

  • skips bundle adjustment: refine is dropped from the default stage set (the mapper runs its own BA), and naming it explicitly raises ValueError

  • reads the scene-root images/ store in place, so COLMAP image names are the keyframe stems

  • shares pairing, overlap, num_retrieved, num_threads and min_registered_frac from BaseSfmCreator

Downstream stages read pointcloud.zarr unchanged; with no confidence, mesh and splats depth targets keep every pixel and the feature lift uses uniform weights.

Registered subset:

  • below min_registered_frac of the keyframes registered: RuntimeError

  • above it: depth, names and keyframes are filtered to the registered stems, with a warning

  • downstream stages read only the frames named in the zarr’s image_paths attr

SfM backends for pointcloud.method: sfm: InstantSfM (global), COLMAP and hloc (incremental).

  • every creator is a BaseSfmCreator: create_pointcloud(images_dir, out_dir, model_dir) -> PointcloudResult

  • the COLMAP model is written to model_dir, image names as stems

  • SFM_CREATORS maps the backend config key to its creator

SIFT database and pairing#

instantsfm and colmap build their SIFT database through ensure_sift_database:

  • GPU SIFT with the CUDA pycolmap build (pycolmap-cuda12) and a visible GPU, else CPU capped at num_threads

  • *retrieval pairings fetch COLMAP’s vocab tree once into ~/.cache/collab_splats/ (sha256-pinned)

  • reused while its image set and matching params match; otherwise rebuilt

pairing

pycolmap matcher

sequential

match_sequential, overlap N, quadratic_overlap=False (i with i+1..i+N)

retrieval

match_vocabtree, num_images = num_retrieved

sequential+retrieval

match_sequential as above + loop_detection=True (loop_detection_num_images = num_retrieved)

exhaustive

match_exhaustive

  • loop detection fires every loop_detection_period frames (pycolmap’s default, 10), so sequential+retrieval is not the same pair set as hloc’s

pycolmap SIFT database helpers shared by the sfm creators.
