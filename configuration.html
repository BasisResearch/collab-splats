Reconstruction Pipeline Configs#

All pipelines start from default template base.yaml — this file holds the defaults for each stage. If a separate file is specified (e.g., MYFILE.yaml), the file only overrides what differs from base.yaml. Running the pipeline and its outputs are covered in the main README.

  • Overriding defaults

  • Stages

  • Options by stage: preproc · pointcloud · mesh · semantics · splats · localization · reconstruction_quality_report

Overriding defaults#

Three layers, applied in order (later wins):

  1. base.yaml, or --base-config FILE.yaml in its place

  2. --config MYFILE.yaml: merged key by key over base.yaml

  3. --set key=value: one dotted key, repeatable

# configs/my_run.yaml: indoor scene, denser frames, no semantics
preproc:
  fps: 3.0
mesh:
  use_convex_hull: false
semantics:
  enabled: false

  • input_path and output_path are required; the CLI sets them from each input and <output-root>/<scene>, overriding any config value

  • every backend folder saves its merged config as <backend>/run_config.yaml; pass it to --config to reproduce a run

  • after changing a config, re-run only the affected stages with --stages <stage> --overwrite

preproc#

Preproc measures every frame once (video_quality_report.json, reused; delete it to re-measure), then picks keyframes that pass preproc.quality.

  • fps (default): fixed time between frames, so the baseline between frames stays the same for any video length

  • uniform: exactly max_frames, evenly spaced; fewer when fewer frames pass the gate

  • optical_flow: spaced by motion, up to max_frames

  • max_frames: 300 is VGGT-Omega’s GPU limit; it caps fps past ~2.5 min at fps: 2.0

  • a directory input takes every image in filename order; only undistort applies

# Fixed 150 frames, evenly spaced
preproc:
  frame_selection: uniform
  max_frames: 150

pointcloud.bundle_adjustment: the refine stage

The refine stage refines feedforward poses against feature tracks and rewrites the pointcloud in place, so the point count can change. The zarr is rewritten whole, which drops the localization database; after --stages refine, re-run every later stage that ran (splats, mesh, semantics, localize, reconstruction_quality_report) with --overwrite.

# Reprojection + depth only, no photometric term
pointcloud:
  bundle_adjustment:
    use_photometric: false

pointcloud.loop_closure: long videos

Loop closure splits a long video into windows, reconstructs each, and joins them through a pose graph with loop edges between revisited places. true turns it on with the defaults below; a dict sets keys.

# Long video: windows of 50 frames, no loop retrieval
pointcloud:
  loop_closure:
    submap_size: 50
    lc_retrieval_threshold: 0.0

mesh#

We fuse depth into a TSDF volume, clean and smooth the mesh, then texture it. The voxel size follows the scene’s depth, so the defaults hold across scales; the reasoning behind each knob is in the mesh API docs.

mesh:
  use_convex_hull: false

semantics#

We extract 2D features per frame, compress them with an autoencoder, and lift them onto the points; with a mesh, talk2dino, maskclip and ocr_lens also lift onto its vertices. Extractors run in order and each writes its own store, so they coexist. Details in the semantics API docs.

# Talk2DINO only, uncompressed
semantics:
  extractors: [talk2dino]
  n_components: null

splats#

3dgs keeps thin structure and trains faster; 2dgs (surface-aligned) gives better surfaces. For the best surfaces use scaffold + 2dgs as the mesh source.

# Best surfaces: scaffold 2DGS as the mesh source
splats:
  enabled: true
  representation: scaffold
  primitive: 2dgs
mesh:
  source: splats

localization#

The localize stage caches per-frame features so query images can be located in the scene later. The retrieval model is stored with the cache, so queries always match it.

# LoMa matcher instead of XFeat
localization:
  matcher: loma
