The on-disk layout is named by helpers rather than string-built: `<extractor>.zarr` (2D patch cache, `(N, D, H_p, W_p)`), `<extractor>_lifted.zarr` (`(P, latent)`) and `<extractor>_ae.pt`, discovered through `cache_store_path` / `lifted_store_path` / `ae_path` / `find_lifted_extractor`; the `_lifted` suffix is load-bearing because both stores share one flat dir. **Compression:** `FeatureAutoencoder` lost its regularization head, `lr_scheduler` and `hidden_dim` — nothing in the repo passed any of them, and hidden width is now derived (`max(64, 2 * latent_dim)`). `save`/`load` take a weights **file** path; the old dir+extractor form mkdir'd whatever it was handed, so a filename silently became a directory. `fit` trains in place and returns nothing — its metrics land on the instance as `recon_cosine` / `recon_mse` / `epochs_run`, and `save` writes them into the checkpoint. Recently completed (2026-09-05): **preproc-centralization** — `collab_splats/preproc` rebuilt around one rule: **measure the whole video, filter it, then sample from what survives.** Five phases ([spec](specs/2026-09-05-preproc-centralization-design.md) · [plan](plans/2026-09-05-preproc-centralization.md)).

**Phase A — the store is COLMAP-shaped.** `frame_store.py`/`FrameStore` deleted for `frames.py`: keyframes are `images/frame_NNNNNN.png` plus a `frames.json` manifest (`write_frames`, `read_frames`, `read_manifest`, `frame_paths`, `frame_idx_from_path`). PNG at compression level 1 (lossless) — level 9 costs 10x the time for 11% of the size, measured. Every consumer (sfm, feedforward, semantics, geometry, mesh, dashboard, evals) reads the directory directly, so `pointcloud/sfm.py` no longer stages its own JPEG copy and `feedforward/base.py` no longer writes a transient export. **`frames.zarr` is not read anywhere — existing scenes need `preprocess(overwrite=True)`.**

**Phase B — the filter actually filters.** `filter_frame_quality` was a static laplacian threshold that cut **zero frames on every video measured**. It is now a robust z-score — MAD on `log(laplacian)`, cut at `sharpness_k=2.0` standard deviations below the median, plus a `max_clipped_frac=0.25` exposure gate — which is per-video by construction and needs no tuning. **HARD GATE, measured: GH010229 (13,115 frames) 5.11% cut (670 frames), tutorial video 14.53% (347)** — the gap tracks the real quality difference between the two captures, which is the point of a per-video statistic. All three samplers now draw from the eligible pool rather than the raw index range: `sample_uniform`, `sample_fps` (which snaps to the pool and delegates its stride to `context_indices`, moved here from `video.py`), `sample_optical_flow`. **`search_radius` retired everywhere** — the blur-substitute walk is gone; a rejected frame is simply not in the pool.

**Phase C — undistortion is two functions, no class.** `DistortionProfile` and `estimate_camera_distortion` deleted. `calibrate_camera(...) -> pycolmap.Camera` and `undistort_frames(frames, camera) -> (frames, new_camera)`: pycolmap picks the undistorted framing, cv2 does the pixels. **Breaking framing change — `undistort_frames` returns a LARGER image than it was given** (pycolmap's default keeps the full valid region instead of cropping to the inscribed rectangle) and a new camera to match, so callers must use the returned camera and not the one they passed in. `run_sfm` undistorts the VDA context stream at SOURCE resolution before any downscale, or the context frames and the keyframes stop agreeing on framing.

**Phase D — decode is in-process.** `get_video_info`, `iter_frames` and `extract_frame` run on PyAV; the `ffmpeg`/`ffprobe` binaries are no longer required on PATH and `av` is a direct dependency. **Measured: full linear scan 76.2 s vs the ffmpeg pipe's 89.2 s (1.17x), sequential 400-frame decode 2.19x, single random frame 10x, output pixel-identical (maxdiff 0).** The one PyAV strategy that is *slower* — seek-per-index over a scattered list, 97.4 s, because every seek lands on a keyframe and re-decodes forward — is deliberately not used; scattered reads go through the linear scan. **HARD GATE: a synthesized rotated-video fixture** proves `get_video_info` reports DISPLAY dimensions (rotation applied) and that decode matches them — PyAV hands back the STORED orientation where the ffmpeg binary auto-rotated, so this was a silent W/H swap waiting on any phone-shot portrait video. `decode_context` moved to `pointcloud/sfm.py`, the only module that uses it.

**Phase E — the docstring rule, enforced.** Every public `preproc` function documents its parameters under `Args:` and its result under `Returns:`. `tests/preproc/test_docstrings.py` walks `preproc.__all__` and fails the build otherwise; the Args check is anchored to line starts, because a bare `f"{p}:" in doc` substring match passes on a parameter name that appears anywhere in prose. Also gone: `plot_disparity_sensitivity`, `plot_quality_examples`, and the qa pair-motion four collapsed into one `compute_pair_motion`.

**Size: 2,268 → 2,106 raw lines, but AST-executable lines 1,211 → 999 (−17.5%)** — the raw number understates it because Phase E deliberately *added* ~180 lines of Args/Returns documentation. Per file (executable): `video.py` 183→103, `undistort.py` 122→77, `viz.py` 316→255, `sampling.py` 272→248, `qa.py` 208→202, `frame_store.py` 79 → `frames.py` 78.

**Breaking changes for callers outside this repo:** `FrameStore` is gone (read `images/` + `frames.json`); `filter_frame_quality`'s kwargs changed (no threshold, no `search_radius`); `undistort_frames` takes a `pycolmap.Camera` and returns a larger image plus a new camera; `preproc.video.context_indices` moved to `preproc.sampling` and `decode_context` to `pointcloud.sfm`.

Recently completed (2026-08-27): **depth-align-affine-2dgs-surface** — a contiguous VDA context stream, affine-in-disparity depth alignment, the 2DGS median-depth surface levers, and the measured grid that ranks them ([design](specs/2026-08-26-depth-align-affine-2dgs-surface-design.md) · [plan](plans/2026-08-26-depth-align-affine-2dgs-surface.md) · [results](specs/2026-08-26-depth-align-grid-results.md)). **Preproc:** `context_indices` builds one constant-rate source grid that `sample_fps` now delegates its stride to, so keyframes are a subset of the context grid by construction; `decode_context` decodes that grid in chunks, undistorting at source resolution before the downscale to a 518 short side, and refuses a short or overrunning decode rather than shifting rows against their images; `_sample_by_quality(candidates=)` snaps targets and blur substitutes onto the grid, sizes its window on the narrowest target gap, and dedups collisions with a warning naming both causes. **SfM:** `generate_vda_depth(keep_rows=)` runs VDA over the context stream and keeps only the keyframe rows; `align_depth_affine` fits per-frame affine-in-disparity coefficients with a one-sided far bound (p99 of the frame's own depth, not its max — a single sky pixel rejected 78/300 frames, p99 rejects 14/300), falling back to scale-only per frame with one counter per cause and a relative-disparity residual in the log; `pointcloud.instantsfm.depth_align: scale|affine` selects the model (`DepthAlignModel` names the pair once) and `random_seed` seeds InstantSfM's `RUNTIME_OPTIONS`. **Splats:** 2DGS renders keep `median_depth` and its finite-differenced normal, `splats.zarr` carries `median_depth`, and `losses.normal_consistency.depth_ratio` blends the RaDe-GS median normal (2dgs-only, range-checked, bool-rejected — as `loss_weight`'s `weight`/`end_weight` now are, since yaml reads `weight: yes` as `True`). **Mesh:** `mesh.splat_depth: expected|median` picks which rendered depth TSDF fuses. **Wrapper:** the VDA depth cache moved out of `_run_sfm` into `_ensure_vda_depth`, stamped with the inputs that generated it so a changed rate regenerates. **Measured** on GH010229 (300 keyframes, 12k steps): `depth_align: affine` 20.729 dB vs `scale` 20.805; `depth_ratio: 0.6` 20.908/0.6831, its +0.10 dB the only PSNR win — and it does NOT transfer to the mesh. The mesh lever is `splat_depth: median`, which is fuse-time and free: 3.3-6.5x fewer components for 22-54% fewer vertices, no visible softening, its only cost holes on grazing surfaces. Distant sloppiness is voxel-bound, not depth-mode-bound: far foliage is a smooth blob at voxel 0.2 either way, and near detail (cobbles, door ribs, railing spindles) appears only at 0.1, where median keeps it at 61k speckle components against 318k. Defaults unchanged pending the owed defaults pass.
