# LC Fix: Loop Application (Phase D) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make applied loop closures correct: fix the poses-None drop (spark, mapanything no-op) and replace the inverted, unscaled direct loop edge with VGGT-SLAM's scale-reconciled 3-constraint chain (omega catastrophic). Gate: re-run the chess-d5 probe — spark 21/21 loops + ATE ≤ SLAM's 0.0455; omega LC HARMLESS (**hard gate** — see Task D); mapanything loops applied > 0. Beyond the gates, omega LC should ideally *improve* long-scene alignment, not merely do no harm — Task D owns that.

**Architecture:** Verify contract widens from `(accepted, poses|None)` to `(accepted, lc_data|None)` where `lc_data = {"poses": (2,4,4) w2c float32, "world_points": (2,H,W,3)|None, "conf": (2,H,W)|None}`. The LC `Submap` carries the points/conf. `run_pose_graph_optimization` builds each loop as 2 graph nodes + 3 edges (anchor A: query→LC0 scaled; inner: LC0→LC1; anchor B: LC1→detected scaled), mirroring `third_party/VGGT-SLAM/vggt_slam/solver.py:add_edge` (solver.py:118-170, 262-295). All relatives use the graph's own `H_inner = P_prev @ inv(P_next)` convention (verified zero-error in gtsam BetweenFactorSL4, 2026-07-08 numeric test; the old `inv(P0) @ P1` edge is its exact inverse when `P0≈I`).

**Design facts (verified 2026-07-09, file:line in probe session):**
- spark native verify forward already computes `pose_enc` (B,S,9), `depth` (B,S,H,W,1), `depth_conf` (B,S,H,W) (`third_party/vggt_spark/vggt/models/vggt.py:62-100`); `pose_encoding_to_extri_intri(pose_enc, hw)` → w2c (2,3,4) (`vggt/utils/pose_enc.py:62-124`); non-verify `_forward` shows usage (`vggt_spark_creator.py:162-168`). world_points = unproject depth (upstream: `unproject_depth_map_to_point_map(depth, extrinsic, intrinsic)`, solver.py:276).
- vggtx (`vggtx.py:429-486`) and omega (`vggt_omega.py:321-356`) verify features return `{"q","k","poses"}` — poses only, no points. lc_data gets `world_points=None` → anchor scale falls back to 1.0 with a logged warning (direction fix still applies).
- mapanything (`mapanything.py:474-538`): verify runs the FULL model; poses derivable via existing `_lc_collate_outputs` recipe (`postprocess_model_outputs_for_inference` → `camera_poses` → `invert_poses` → w2c, lines 331-343). No second forward.
- LC Submap (wrappers.py:319-333) currently omits `world_points`/`world_points_conf` (submap.py:10-22 fields exist, default None). Sequential-edge scale machinery (closure.py:452-511, `estimate_scale_pairwise`, conf fallback chain) is reusable.
- Upstream anchor scale: pixel-aligned pointclouds of IDENTICAL images (LC frame vs original submap frame), conf fallback joint>thr → prior>thr → prior>0, min 100 pts (solver.py:129-151).

**Constraints:** parity harness code (evals/) unchanged except the probe re-run. `tests/mesh`, dashboards etc. untouched. Follow repo style (block comments, one-line docstrings, flat tests). Python: `/opt/venv/reconstruction/bin/python`.
