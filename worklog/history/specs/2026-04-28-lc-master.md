## Verification gate per spec

Each spec ends with:

1. **Unit tests pass** — concrete files listed in spec
2. **Integration test pass** — concrete file listed in spec
3. **Behavior assertion** — numeric check (e.g., spec 2: `output.shape == (N,4,4)`; spec 3: ATE drop on synthetic 3-submap loop)
4. **Reviewer signoff** — invoke `superpowers:requesting-code-review`
5. **Squash-merge to `refactor/core-modules`**
6. **Update WORKLOG.md** — record squash-merge SHA + next spec start

If any gate fails → fix in current branch, do not advance.

## Agent execution protocol

Per spec, run as separate session:

1. **Read** master index + current spec + verification response
2. **Worktree:** `superpowers:using-git-worktrees` to create isolated branch
3. **Plan:** `superpowers:writing-plans` → `worklog/history/plans/2026-04-28-lc-NN-<topic>.md`
4. **Execute:** `superpowers:executing-plans` (TDD discipline per spec)
5. **Verify:** run gate checklist from spec
6. **Review:** `superpowers:requesting-code-review`
7. **Merge:** squash into `refactor/core-modules`
8. **Update WORKLOG.md** + signal next agent
